0. One of the most important operations ElmerGUI does is to prepare a solver input file (sif) for us. As we will see later in the series, not all Elmer models are supported by the GUI, so we will need to write at least parts of the sif by ourselves at some point in the future.


1. Comment starts with '!' .  It can be a inline comment too.

2. All sections start with some keyword or phrase and end eith 'End' .

3. Sequence of sections is NOT very fixed (Except header). It can be anything as long as variables used in the section for numerical values are defined before.

4. A section can consist of only comments. That will be treated as if that was not there in the .sif file.

5. There are multiple ways a same thing can be done. 

6. Sections are
 o Header
 o Constants
 o Simulation
 o Solver i
 o Body i
 o Equation i
 o Body Force i
 o Material i
 o Initial Condition i
 o Boundary Condition i
 o Run Control
 o Component i

 ===>  Not all sections are needed.


7. Many keywords defined in SOLVER.KEYWORDS database. Foor others keyword type must be given.

8. Keyword(n,m) indicates a n×m array. It is applicable for Integer and Real.

9. For sections with indexing use continuous numbering starting from 1.

10. include statement may be used to read other files within the SIF file ( eg.,  include material.sif )

11. Scripting by MATC or by LUA.

12. Real valued keyword functions can be used (eg, temp dependent density). It can be done in MATC, LUA, FORTRAN etc.

13. Boundary may be given a body id so that it can have an Equation, Material, Body Force etc. associated to it. (example :  Body Id = 4 ) 

14. Sif file: Run Control ===> New section since 2020 . Provides parametric looping and internal optimization also in transient cases. If used, this section should be the 1st one.

15. "Component" ====> Rarely used new section.  • May define a collection of bodies or boundaries to be used for model lumping etc.  • Main usage currently in electromagnetics.

16. Coordinate System = "Cartesian 2D" ====>  choices : Cartesian{1D,2D,3D}, Polar{2D,3D}, Cylindric, Cylindric Symmetric, Axi Symmetric

17. Simulation Type = "Transient" ====> Steady State, Transient or Scanning .

18. Each Body has to have an Equation and Material assigned. Body Force, Initial Condition optional.

19. The users should not be afraid to add new atomistic solvers to perform specific tasks.

20. By default each a Solver is executed in order of their numbering. ===> "Exec Solver” keyword can be used to alter this.

21. Conditional statements (in MATC or LUA ) are typically used to define complex material properties, boundary conditions, or initial conditions that change based on space or time.

22. For more complex logic that goes beyond what's practical with MATC, you can define your own functions in an external file 
      (e.g., a Fortran or C++ source file) and then call that function from your .sif file using the Procedure keyword. 
      
23.  You can define parameters at the top of an ElmerSolver .sif file and then use them throughout the file. This is a best practice for making your simulation setup more readable and easier to modify.

     The standard way to define global parameters is within the Constants section.
     
24. The "Run Control" section of an Elmer SIF file is a specialized section that provides an outer-level control loop for the entire simulation. 
    It's used for running multiple cases from a single SIF file, which is particularly useful for optimization, parametric studies, and design of experiments.
    Unlike other sections that define the physics or material properties, Run Control is a powerful tool for automating a series of simulations. 
    It was introduced in recent Elmer releases to handle tasks that were previously done by external shell scripts.
    
25. Data can be saved in various formats --> Gid , Gmsh, Vtk , Vtu , Dx (in one or many of these)

26. Model 67 ===>  can read fields from Gmsh results file.

27. Model 68 ===> Reload Existing Simulation Results.

28. Model 69 ===> Runtime Control of the Input Data

29. Model 59 ===> Internal Cost Function Optimization ===> This solver is an auxiliary solver for optimization problems. As input it requires a cost function computed
      with the previous parameter values, and as output it gives the new parameters for which the cost function will be computed for.

29.  ElmerSolver has a built-in feature to restart a simulation from a previous state, which is essential for long transient calculations. 
           (1) using restart file feature (2) using the last solution as initial condition
           
30. Note : With Elmer most issues you might face are about not setting up the solver properly. These, in my experience, are the most common issues after mesh related issues.

Defining coils currents 

There are multiple ways in Elmer to define coil currents in hierarchical simulations for the Whitney AV solver to compute magnetic fields. Basically one can give "Current Density i", i=1,2,3 or "Electric Potential" which is used to internally compute the current sources in the AV solver.

Now the caveat of the given source is that they must be divergence free. Elmer has built-in automated logic to do this but it only works for the given current density, not for the potential. To control the fixing there is the keyword   "Fix Input Current density = True"

Since quite recently there is a possibility to also compute elemental fields of current density. These basically utilize the discontinuous galerkin features of Elmer where each nodal value is independent between elements. This avoids the intermediate and unnecessary projection to nodes and seems to be very beneficial for the convergence of the linear system of the vector potential.

What are Closed and Open Coils?
===============================

In 3D we need to make a distinction between open and closed coils depending on the termination of the conductor. To the left you see that the closed coil has only one single (high) terminal, whereas the open coil has two: high and low terminals.

This distinction is relevant when setting up the circuit network and the finite element model, as modifications will be required to assign these surfaces with the appropiate boundary conditions in the .sif file.

When using the CoilSolver, some simplifications are made. In the case of a closed coil automatic cuts are made and no boundary conditions are needed (see image below). If the coil is open, the boundary conditions need to be defined on each terminal of the conductor.
